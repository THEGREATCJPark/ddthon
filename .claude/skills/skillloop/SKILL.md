# SkillLoop — Agent 진입점 (C9)

원칙: **자연어 해석은 Claude가, 제품 로직(매칭·적용·검증·카운트)은 기존 CLI/서비스가.**
별도의 키워드 매핑 코드는 두지 않는다. 모든 동작은 사용자가 동일한 `python -m skillloop ...`
명령으로 **단독 재현**할 수 있어야 한다(FR-SURF-3).

## 요청 유형 구분 (중요)

### 1) 명시적 P0 재사용 데모
사용자가 "P0 데모", "run-p0", "재사용 데모 보여줘"처럼 **데모를 명시**한 경우에만:
```
python -m skillloop run-p0
```
- 이것은 **자체완결 데모**다(합성 실패를 스스로 만들어 적용·검증·카운트).
- 보고는 실제 출력의 `reuse=N (counted=..., reason=...)` 그대로. **"실제 업무에 적용했다"고 말하지 않는다.**

### 2) 실제 설치/업무 요청
"이 설치가 안 된다", "X 패키지 설치 좀 고쳐줘"처럼 **실제 업무** 요청이면:
- **절대 `run-p0`로 바꾸지 않는다.** run-p0는 데모이며, 일반 설치 요청을 run-p0로 대체해
  "Skill을 실제 업무에 적용했다"고 보고하는 것은 금지된다.
- 절차:
  1. 실제 실패를 **직접 관찰**한다(실제 명령을 실행해 실패·신호를 확인 — Agent의 탐색 역할).
  2. 관찰한 신호로 재사용 Skill을 **검색**한다:
     ```
     python -m skillloop match --signature <관찰된-실패-신호> [--target <패키지>]
     ```
     - `match`는 승인된 검색 계약(C5)을 호출만 하는 **읽기전용**이다. 적용·카운트를 하지 않는다.
  3. `MATCH`면 출력된 **적용 절차**를 실제 업무 환경에 적용하고 **실제로 검증**한다(Agent의 실행 역할).
  4. **실제 검증에 성공한 경우에만** "이 Skill을 실제 업무에 적용해 해결했다"고 보고한다.
- 실적 카운트는 **검증 성공 경로에서만** 발생한다. 검증 없이 카운트·성공을 만들어내지 않는다.
- 참고(현재 한계): 임의의 실제 업무 대상에 대한 **일반화된 적용·검증·카운트**는 아직
  P1/RU4 확장(소유: A) 대기다. 그 전에는 `match`(검색)까지 연결되며, 실적 반영을 단정하지 않는다.

### 3) 조직 현황 / 상태
```
python -m skillloop status       # 한 줄 요약(하단 상태줄과 동일 소스)
python -m skillloop dashboard    # http://127.0.0.1:8765/ 로컬 읽기전용 대시보드
```
- 게시(PUBLISHED)는 lifecycle 조회(계약7)가 연결됐을 때만. 미연결이면 "확인 불가/상태 조회 미연결"로
  표시하며 0건·특정 상태로 **추정하지 않는다**. 실제 재사용과 DEMO_SEED를 구분해 읽는다.

## 안전·게이트 (항상 유지)
- **원격 Skill 자동 실행 금지**(NFR-SEC-4): 원격/타 환경에서 온 Skill은 **명시적 사용자 확인 후에만** 실행.
- **게시 게이트 유지**: 검증 없이 SHAREABLE/PUBLISHED로 승격하지 않는다.
- **비밀·원본 업무 데이터**를 Skill/출력에 포함하지 않는다(합성만, NFR-SEC-1).
