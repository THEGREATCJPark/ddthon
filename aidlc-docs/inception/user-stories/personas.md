## PER-1 — 사내 엔지니어 (Primary)

- **누구**: 코딩 경험이 적은 사내 엔지니어. Coding Agent(Claude Code)를 이용해 데이터 분석·업무 자동화를 수행한다.
- **동기**: 사내환경 제약(패키지 공급 경로, 보호 문서 접근 등) 때문에 **반복해서 막히는 문제**를, 팀의 검증된 해결 경험으로 빠르게 넘기고 싶다.
- **고충(Pain)**: 같은 실패·탐색을 반복한다. 해결 방법이 개인 대화에만 남아 재사용이 어렵다.
- **성공 기준**: 검증된 Team Skill이 실제로 재사용되어 업무가 완료되고(P0), 해결책이 없던 문제도 대안 절차를 찾아 업무를 완료(P1)한다.
- **주체 명시**: PER-1의 요청을 받아 **실제 업무 수행(검색·적용·설치·읽기·계산·후보화)을 실행하는 주체는 Agent**다(FR-SURF-1). PER-1은 자연어로 요청·환경 사실 확인을 담당한다.

## PER-2 — 팀 리뷰어 (이해관계자)

- **누구**: 새 Skill 후보를 검토·승인/거절하고 게시 여부를 판단하는 팀 구성원.
- **동기**: 검증되지 않았거나 안전하지 않은 절차가 팀 자산으로 게시되는 것을 막고, 신뢰할 수 있는 Skill만 공유되게 한다.
- **고충**: 후보의 내용·재현 가능성을 확인할 근거가 없으면 승인할 수 없다.
- **성공 기준**: 사람 검토 + 독립 Replay가 통과한 **정확히 그 후보만** Git 공유 대상(이번 시연: `team-skill-store` branch)에 게시된다(FR-P1-7). 원격 push 성공 확인 후에만 공유 완료(PUBLISHED)로 표시된다.

## PER-3 — 다음 Agent 재사용자 (이해관계자)

- **누구**: PER-1과 동일/다른 사용자가 새로운 문제에서 사용하는 **다음 Agent**, 그리고 그 Agent를 사용하는 사용자.
- **동기**: 이전에 검증·게시된 Team Skill을 받아 같은 종류의 문제를 처음부터 다시 풀지 않고 재사용한다.
- **고충**: 무관한 Skill을 잘못 선택하거나, 재사용 실적이 실제 성공과 시연용 이력으로 뒤섞이면 신뢰가 떨어진다.
- **성공 기준**: 결정적 검색 + applicability 확인으로 맞는 Skill을 골라 실제로 재사용에 성공하고, 실적이 정직하게 집계된다(FR-MATCH, FR-USAGE).
- **주체 명시**: **Agent가 업무 수행 주체**로서 검색·적용·검증을 실행한다.
