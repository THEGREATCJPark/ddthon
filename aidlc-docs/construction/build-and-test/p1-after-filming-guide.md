## 촬영 장면 / 짧은 자막
1. 업무 요청 입력: “사용자는 평소처럼 업무만 요청합니다.”
2. 실제 직접 읽기 실패: “사내 문서를 일반 Python 방식으로 읽지 못했습니다.”
3. 실제 Team MATCH: “팀이 이미 검증한 환경 접근 방법을 찾았습니다.”
4. P1 실행 확인: “이 문서에 접근 방법을 적용하도록 승인합니다.”
5. 접근 및 현재 문서 해석: “환경 접근 방법은 재사용하고, 이번 문서의 데이터는 새로 읽습니다.”
6. 실제 업무 결과와 차트: “실제 데이터와 다음달 예상치를 구분해 확인합니다.”
7. 실제 counted=True/+1: “새 Skill을 중복 생성하지 않고, 검증된 재사용을 기록합니다.”
8. 엔딩: “첫 Agent의 해결 경험이 다음 Agent의 출발점이 됩니다.”

예상 상태: 실패 → MATCH → exact 실행 확인 → 접근/현재 업무 배치 확인 → 결과/차트 → candidate_delta=0, 실제 재사용+1. 실패하거나 다른 결과가 나오면 원본을 보존하고 해당 장면을 성공으로 꾸미지 않는다. GitHub 반영 완료는 실제 sync 성공이 있을 때만 자막에 넣는다. 초기 팀 실적은 이미 존재하는 이력이며 0으로 초기화하지 않았다.

## 파일과 로그
- `warm/`: Agent 작업 영역. XLSX/연결정보/기존 환경 Skill이 있음. 업무 답·task-mapping·차트는 미리 생성하지 않았다.
- `Open-warm.cmd`: 운영자용 문서 재열기. 암호 입력 없이 준비된 문서를 연다.
- `operator/skill-provenance.json`: 기존 exact Skill의 원본 검토/Replay/게시 근거와 수신 근거.
- `operator/received-skill-descriptor.json`: 제품이 실제 수신한 descriptor 원문. 단독 Markdown 절차를 꾸민 것이 아니며 --skill-file에 바로 넣을 검증된 문서라고 주장하지 않는다.
- `operator/readiness.json`: 읽기 실패·MATCH·환경 접근·원본 보존·카운트 무변경 사전 확인.
- `Start-filming.ps1`: 새 Claude 실행. 종료 후 해당 workspace의 새 JSONL 로그를 operator/private-logs-*에 복사. 원본은 Claude 프로젝트 로그에도 남는다. 로그 미발견을 성공으로 표시하지 않는다.
- raw 로그에는 대화·도구 결과가 포함될 수 있다. 외부 전달 전 자격증명/개인정보 확인 후 공개용 사본을 만든다. 원본은 삭제하지 않는다.

## 비교 측정 대기
최신 Excel 기반 실행기/입력3개/task/boundary/model/version/검증기 ZIP 필요. 그때 공통 hash와 사전 준비 상태를 대조한다. 지금 촬영의 사용자 승인 대기시간과 수동 개입은 기록하되, 무인 비교 시험 결과와 합치지 않는다. 전체 제품 Warm과 Skill 원문만 제공한 조건은 별개다.
