# 적용 전 PC: 현재 수동 3회 시연 프로토콜

기존 Paired/VM 구축 준비는 보류합니다. 과거 SAFETY_STOP 실행기는 풀거나 복사 실행하지 않습니다. 이번에는 사용자가 일반 Claude Code 세션에서 직접 3회 수행하고 화면을 녹화합니다. 모델 실행은 해당 PC 사용자가 시작합니다.

이 ZIP은 기존 v2 입력과 다른 **메인 PC 현재 시연 입력**입니다. 옛 입력/로그를 덮어쓰지 말고 별도 새 실행으로 보관하세요. 세 회차 입력은 동일한 바이트입니다(동일 사례 반복). 기존232.26초/511.41초와 합산하지 않습니다.

## 준비

1. ZIP은 운영자 폴더에 풉니다. 각 회차용 새 Agent 작업 폴더에 inputs/round-N의 XLSX 하나만 복사합니다. README/task/protocol/기존 출력/해결 절차/Skill은 작업 폴더에 넣지 않습니다.
2. SkillLoop·학습된 환경 Skill·MCP·이전 대화를 로드하지 않는 정상 CLI 세션을 준비합니다. 기존 사용자 설정은 삭제하지 말고 이번 실행에서 로드 차단한 설정과 확인 근거를 기록하세요. CLI를 일반 대화형 권한 확인 모드로 사용합니다. 과거 자동 실행기의 권한 자동승인/보호 중단 우회는 사용하지 않습니다.
3. Claude Opus4.8, medium. Python/Excel/library 실제 버전은 기록하되 녹색 checker를 위해 복호화 패키지를 Agent 환경에 추가하지 마세요. 메인 제품 Agent는 제품 .venv Python3.14이며, 별도 비교 준비용 Python3.13은 이번 제품 시연 런타임이 아닙니다. 버전 차이는 관측 비교의 한계로 표시합니다.
4. 문서는 닫고 시작합니다. 작업 요청 후 읽기 실패가 확인되고 대화에서 환경 확인이 필요한 시점에 사용자가 해당회차 문서를 직접 엽니다. 운영자용 공개 데모 암호는 nowhere입니다. 암호를 Agent에게 전달하지 마세요. 그 후 사용자 발언은 '이상하네, 나는 직접 열면 내용이 보이는데?'로 맞추고 추가 질문/힌트가 생기면 전부 기록합니다. COM/해결 경로/정답값은 알려주지 않습니다. 메인과 발언 시점 차이는 기록으로 남깁니다.

## 안전과 진행

사용자가 화면을 보며 직접 진행합니다. 앱/프로세스 전체 종료, 작업 범위 밖 변경, 자격증명/다른 문서 접근 명령은 승인하지 말고 중단 사실을 기록하세요. 그런 명령이 자동 실행되는 환경이면 시작하지 말고 자동 승인 설정부터 이번 세션에 한해 해제합니다. 관찰/녹화는 OS 격리 증거가 아니며 같은 권한의 원본 로그 무결성을 보장한다고 주장하지 않습니다.

동일 task.txt 요청을 각1회 입력합니다. 600초는 이전 비교의 기준이었으나 이번 수동 시연에서는 완료/중단 시점과 실제 소요시간을 그대로 기록하고, 제한을 적용하면 양쪽에 같은 기준과 기록을 남깁니다. 실패/중단을 성공 실행으로 교체하지 않습니다. 중간 /clear 금지. 종료 전 /cost 화면을 캡처하고 /exit. 회차별 세션 ID·원본 JSONL(하위 Agent가 있으면 관련 로그 포함)·화면 영상·차트·분석파일·사용자 개입시각을 보존합니다.

## 반환

회차마다 성공/실패/중단, 실행시각, 원본 대화, /cost 캡처, 결과/차트, 오류/재시도/힌트와 해당 이벤트를 전달하세요. 최종 토큰이 없으면 missing이며 부분 usage를 중복합산하지 않습니다. 업무 성공은 실제 데이터·계산·차트를 확인해 판정하고, 검증기의 수동 입력 PASS만으로 확정하지 않습니다.

이쪽 NO_SKILL과 메인 FULL_PRODUCT_COLD는 전체 제품 사용 유무의 관측 비교입니다. 환경metadata·사용자개입·PC/런타임 차이가 있으므로 Skill 하나의 인과적 향상률 또는 기존 Paired 실험 완료로 표현하지 않습니다. 기존 AI-DLC Build & Test에 실행계획 정정과 실제 근거만 추가합니다.
