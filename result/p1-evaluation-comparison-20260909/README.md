# Agent SkillLoop — P1 비교 데이터와 심사 대응

2026-09-09 · 적용 전3회 / 적용 후 Cold4회 · 관측 비교

## 제출에 사용할 핵심 결론

**동일 Excel 업무에서 SkillLoop 미사용 파일럿3회는 업무를 완료하지 못했다. SkillLoop를 사용하고 열려 있는 환경 정보를 제공한 Cold4회는 모두 실제 데이터 읽기·예측·차트 생성까지 완료했다.**

이 자료는 업무 완결성의 관측 근거다. 환경 정보·권한 방식·PC가 달라 SkillLoop 단독의 속도 향상률이나 일반적 성공확률을 증명하는 실험은 아니다. 모든 적용 후 실행은 기존 P1 Skill이 없는 Cold이며, Warm 재사용 성능 자료가 아니다.

## 1. 다시 확인한 심사 기준

사용자가 제공한 운영진 안내와 저장소 EVALUATION.md 및 requirements.md CON-3을 대조했다. EVALUATION.md는 공식 원문 자체가 아니라 전달받은 안내의 요약이다. 이번에 공식 사이트의 새 공지를 조회했다고 주장하지 않는다.

최종 점수는 **AI 심사40% + 인간 투표60%**다. AI 심사에는 인간 심사위원의 Gating 보정 가능성이 있다.

| AI 심사 항목 | 배점 | 이번 자료가 제공하는 근거 | 아직 과장하면 안 되는 부분 |

| AI-DLC 활용도 | 25 | 사용자 결정→측정 계획→실제 실행→오류 보존→검증·보고의 연결 | 문서 양이나 성공한 로그만으로 충실성을 주장하지 않음 |
| 문제 정의 및 해결 | 20 | 일반 파일 접근에서 막힌 동일 업무를 실제 수치·차트까지 완수 | 단일 사례를 모든 사내 환경에 일반화하지 않음 |
| 창의성 | 15 | 실패 관찰·NO_MATCH·탐색 결과를 환경 절차 후보로 축적 | 기본 Agent도 COM을 생각할 수 있으므로 COM 사용 자체가 차별점은 아님 |

| 사용성 | 15 | 자연어 업무 요청과 읽을 수 있는 실적/예측 결과 | 사전 환경 연결·Excel 열기 필요, 영어·내부 용어·단위 설명 오류 잔존 |
| 유지보수성 및 보안 | 10 | 원본 무변경, 업무 데이터와 공유 절차 분리, 실제 사람 승인·Replay 게이트 보존 | 지침 준수를 OS 차원의 강제 보안으로 주장하지 않음 |

평가는 문서 개수보다 앞선 결정이 실제 코드·동작으로 이어졌는지에 달려 있다. 현재 비교 자료는 **문제 해결과 완성도**에 특히 도움이 된다. 전체 저장소를 이번에 재심사하지 않았으므로 공식 점수나 예상 투표 점수를 임의로 산출하지 않는다.

## 4. 차별성을 설명할 때 중요한 실제 관찰

- 적용 전3회차도 COM을 자발적으로 제안했다. 하지만 새로 열기·Excel 전체 종료가 포함된 명령이 거부됐고, 이후 자체 파서·암호 시도로 돌아가 업무를 마치지 못했다. “기본 Agent는 해결책을 전혀 생각하지 못한다”는 주장은 틀리다.
- 적용 후4회는 실제 업무를 마치고 **환경 접근 절차만 후보로 생성**했다. 업무 값·시트 배치·차트는 공유 Skill에 넣지 않는 흐름이다. 각 회차 후보+1, 기존 Skill 재사용+0이다.
- 별도 수동 세션 e518ab42에서는 실제 사용자 승인→독립 Replay PASS→Git 게시 e302bf213679a038fea04e5058188096cb96c24b까지 확인했다. 이것은 이번4회에 합산하지 않고 **게시 기능 증거**로 따로 연결한다.
- 다음 Agent의 빠른 활용이라는 메시지는 P0의 기존 Skill 재사용 증거 또는 별도의 P1 Warm 실행으로 뒷받침해야 한다. Cold4회만으로 재사용 성능을 증명할 수 없다.

## 5. 조건 차이와 응답 품질

공통 입력 XLSX의 SHA256은 `fcdbf97a191a7ba1d6c5921183fed9ce03594b11b7621adafd6c5a25e8bfa935`이며 업무 문장은 같다. 양쪽 모두 Excel을 미리 열었다. 하지만 적용 후에는 처음부터 “직접 열 수 있고 현재 열어두었다”는 환경 사실과 탐색 요청을 제공했고, 적용 전에는 알려주지 않았다.

또한 적용 전은 다른 PC의 수동 도구 승인, 적용 후는 auto 비대화형 실행이다. Python·라이브러리 버전과 캐시 상태도 동일하게 통제하지 않았다. 적용 후는 C9와 기존 제품 함수를 이용하며, Skill 원문 하나만의 효과를 분리한 실험이 아니다.

기능 PASS와 표현 품질은 구분한다. 적용 후1회는 다중 Excel 탐색이 길고 확인되지 않은 Protected View 가설이 있었다.2회는 중간 영어 표현,3회는 구현 용어,4회는 `total_output`을 문서 단위처럼 설명한 문제가 있었다. 원문은 수정하지 않았고, 이 문제들은 사용성 개선 대상으로 남겼다.

## 6. 심사·갤러리에 바로 쓸 문구

### 핵심 소개

> 사내 환경에서 Agent가 막히면, 이미 해결한 문제는 팀 Skill로 재사용하고 처음 겪는 문제는 탐색해 해결합니다. 성공한 환경 접근 방법은 검토·검증을 거쳐 팀이 다시 쓸 수 있는 자산으로 남깁니다.

### P1 비교 캡션

> 동일 Excel 업무 관측: SkillLoop 미사용3회는 업무 미완료. SkillLoop를 사용하고 열려 있는 환경 정보를 제공한 Cold4회는 모두 실적 읽기·예측·차트까지 완료했습니다. 환경과 사용자 개입이 달라 성능 향상률을 측정한 통제 실험은 아닙니다.

### 별도 게시 장면 캡션

> 이번에 발견한 접근 절차를 사람 승인과 독립 재검증 후 Git 기반 팀 Skill 저장소에 게시했습니다. 업무 데이터는 공유하지 않습니다.

### 시연 화면 배열

1. 적용 전 실제 실패/추가 자료 요청 장면.
2. 적용 후 실제 NO_MATCH→탐색→차트 결과 장면.
3. 별도 실제 사용자 승인→Replay→게시 장면.
4. 기존 Skill 재사용 장면은 P0 또는 검증한 P1 Warm으로 구분해 배치.

짧게 편집한 영상 길이를 실측 처리시간으로 표시하지 않는다. 이번 자동4회는 영상 녹화가 아니라 전체 로그·실제 차트 기록이다. 실제 수동 촬영 영상과 실행 식별자를 구분한다.
