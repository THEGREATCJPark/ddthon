# P0: NO_SKILL 4–6회와 팀 Skill 적용 3회 비교

## 판정과 회차 선정

**비교용 적용 전은 4·5·6회 전체**, 적용 후는 기존 1·2·3회 전체를 사용한다. 추가 제출된 연속 3회이고 동일 입력·실행 프로토콜과 독립 검증 기록이 갖춰져 있다. 느리거나 실패한 회차를 제거하지 않았다. 사후 선택이며 사전등록된 표본 선택은 아니다. 기존 적용 전 1·2·3회도 아래 표와 원본 파생 근거에 모두 보존했다.

적용 전 선정 3회: **중단·성공·성공(2/3)**. 적용 전 누적: **4/6 성공**. 적용 후: **3/3 성공**. 이는 소규모 관측 결과이며 일반 성공률이 아니다. Skill 없는 Agent도 스스로 공급원을 찾아 해결했다. 제품의 근거는 ‘불가능을 가능하게 함’보다 ‘이미 검증된 팀 절차를 재탐색 없이 활용함’이다.

**시간 해석:** 적용 전 4회차 86.385초는 해결 시간이 아닌 중단 답변까지다. 5회차의 import·__version__·ok 검증은 173.231초, 엄격한 importlib.metadata 확인은 종료 후 운영자가 197.784초에 했다. 6회차는 Agent가 metadata/import를 213.595초에 확인했다. 이 서로 다른 종료점을 단일 평균 성공시간이나 절감률로 합치지 않는다. 적용 후 primary는 제품 검증·카운트 시점이며 후속 독립 검증/최종 설명 시점은 JSON/CSV에 별도로 있다. 최종 응답은 native text-block timestamp로 화면 스트리밍 종료의 별도 계측값은 아니다.

**6회차 지연:** 첫 설치 명령 요청부터 승인 기록까지 89.862초의 운영·승인 지연이 있었다. 이를 Agent 탐색 시간이라고 주장하지 않는다. 승인 구간은 겹칠 수 있고 정확한 UI 대기는 미계측이므로 합산 대기시간을 임의로 빼지도 않았다. 적용 전 manual, 적용 후 auto 차이가 있다.

## 비교 적합성과 한계

- 두 ZIP의 전체 payload 검증 및 각 6회 native token 재집계 일치. 적용 전 각 최초 미설치/후검증과 PASS/BLOCKED가 일치한다.
- 양쪽 task·requirements·wheel 동일 바이트. requirements SHA256 `0124a81bcc80c1a33a10a5595dbf43ba061eafdddb80afb9c51d14f43d067726`, wheel `d02bbd696c3c33a206924e4982742b7faa58f5c12756d858e6265c7c8bc2697b`.
- Claude Opus4.8 / medium / Bedrock / CLI2.1.266 동일. 그러나 적용 전 Python3.13.14·pip26.1.2·manual, 적용 후 Python3.14.0·pip25.2·auto print, PC/cache/허용 도구/경계지침이 다르다. 제품 runtime/정책이 제공된 전체 제품 조건이지 Skill 텍스트 하나만 통제한 실험이 아니다.
- NO_SKILL에서는 이웃 allow 공급원을 Agent가 탐색할 수 있었다. WITH_SKILL은 기존 검증된 절차와 공급원 정책을 사전 연결했다. 측정 중 새 해결법이나 답을 넣지 않았다.
- 실제 오류는 오프라인 기본 공급 폴더의 패키지 부재다. 실제 사내 proxy 차단이나 timeout 실험으로 설명하지 않는다.
- 5회차 ‘옵션 없이 재설치하면 또 실패’라는 최종 설명은 검증되지 않았고 이미 설치된 상태에는 맞지 않을 수 있다. 실제 설치 성공과 별개로 이 문구 한계를 보존했다.
- 신규 모델 실행·제품 수정·웹 수정은 이 보고서 작성 중 하지 않았다. 이전 실패/시간/토큰 기록은 대체하지 않았다. 두 PC의 차이를 Skill만의 성능 개선율로 표현하지 않는다.

## 공개 근거와 재현 추적

`comparison.csv/json`은 적용 전6+후3 전체 자료, `selection.json`은 선정 규칙이다. `before/`와 `after/`에는 각 회차 실제 공개 응답·도구 로그·검증 근거를 보존했다. 원본 ZIP/native는 운영자 PC에 보존하고 원본 SHA와 payload manifest를 `source-integrity.json`에 연결했다. 공개 파일은 개인 home 경로를 `<USER_HOME>`으로 바꾸고 비공개 추론/signature/불필요한 metadata를 제외했다. 명령과 성공/실패 결과는 창작하지 않았다.

적용 후 측정은 당시 로컬 HEAD `ba5f4cf`의 dirty worktree였다. `source-integrity.json`의 protocol에 bootstrap hash를 보존했다. 이 보고서를 배포하는 최신 Git SHA에서 다시 실행한 결과라고 주장하지 않는다. 실제 측정 제품 코드 snapshot의 추가 동결은 최종 마감 검토 사항이다.
