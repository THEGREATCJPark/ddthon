## 성공 검증과 시행착오

세 회 모두 실제 직접 읽기 실패→NO_MATCH→Agent 탐색→WORK_COMPLETE를 로그에서 확인했다. 요청한 실적·예측의 값과 월을 대조하고 각 PNG의 실적/예측 구분을 육안 확인했다. 각 후보+1, 실제 재사용+0이다. 사람 승인·Replay·게시를 생략한 것이 아니라 **이번 업무 측정 범위에서 수행하지 않은 것**이며 게시 게이트는 제품에 그대로 남아 있다.

- 1회: PowerShell/COM 탐색을 여러 번 수정하고 여러 Excel 인스턴스를 조사해 지연. “Protected View일 수 있다”는 가설은 실제 원인으로 검증되지 않았다. 이후 제품 접근 함수가 실제 스냅샷을 확보해 완료했다. 도구 요청33회.
- 2회: Python 문법·COM 객체 취급·procedure 경로 오류가 있었지만 해결해 완료. 도구 요청11회.
- 3회: 콘솔 인코딩을 보정해 실제 시트 이름을 확보하고 완료. 도구 요청10회.

최종 결과는 세 회 모두 실적과 예측을 구분하고 차트를 제시했다. 다만 **제품 구현 용어 노출과 언어 혼용은 여전히 개선 여지가 있다.** 1회는 “지원 어댑터/procedure/스냅샷” 설명이 길었고,2회는 “Syntax slip — cleaning up.” 등의 영어가 나왔다.3회는 중간에 “보호된 상태/관리형 문서”라고 표현해 모든 회차가 요청한 NASCA 문구로 고정되지는 않았다. 원문을 보기 좋게 수정하지 않고 responses.md에 남겼다.

즉 **업무 완결성은3회 확인했지만, 항상 빠르고 짧은 Cold UX가 완성됐다고 하기는 어렵다.** 남은 핵심은 다중 Excel 인스턴스 탐색의 편차와 중간 설명 품질이다. 이 측정 도중 제품을 수정하거나 재실행해 수치를 개선하지 않았다.
