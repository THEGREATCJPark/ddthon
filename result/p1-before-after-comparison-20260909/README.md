# P1 적용 전·후 관측 비교 및 평가

2026-09-09 · 동일 Excel 업무 사례 · 적용 전 3회 / 최신 적용 후 Cold 1회

## 결론

**적용 전 3회는 업무를 끝내지 못했고, 최신 SkillLoop 적용 후 Cold 1회는 데이터 읽기·예측·차트 생성과 후보 승인·Replay·Git 게시까지 완료했다.** 현재 자료는 제품이 문제 해결과 경험 축적을 끝까지 연결했다는 사례 증거다. 통제된 성능 실험이나 기존 Skill 재사용 속도 검증은 아니다.

적용 후에도 처음에는 P1 Skill이 없었다. 따라서 이 비교의 정확한 이름은 **“SkillLoop 없는 탐색 ↔ SkillLoop를 사용하는 최초 문제 해결”**이다. “학습된 Skill 적용 전후” 또는 Warm 비교로 소개하지 않는다.

## 1. 확인한 자료

- 수신 ZIP: `P1-Cold-Three-Pilots-Results.zip`
- ZIP SHA256: `b5251c26f83ca545f022a363127ba1048ee8e82b25621993f99572085e72deba`
- manifest의 65개 payload 크기·SHA256 전부 일치. 이는 전달 무결성 확인이며 독립적인 측정 인증은 아니다.
- 각 회차 원본 JSONL의 assistant message.id 중복을 제거해 토큰 재집계. 3회 모두 보고와 일치.
- 원본 도구 요청·오류 개수, 시작/종료 시간 차이를 재계산. 최종 응답 및 3회차 COM 명령 본문 확인.
- 적용 후 원본 스냅샷 hash와 업무/사용자 결과 시점의 토큰 합계 재확인. 기존 실제 차트 검토·원격 게시 확인 기록과 연결.
- 수신 ZIP 내부 실행기·Python 코드 실행 없음. 원본 ZIP과 로그를 수정하지 않았다.

## 2. 업무 결과와 시간

공통 요청: “AAAAA01_직전_3달_생산량.xlsx를 읽고 다음 달 예상 생산량을 포함한 추세선을 그려줘.”

| 실행 | 업무 결과 | 요청부터 결과까지 | 실제 데이터·차트 |
| --- | --- | ---: | --- |
| 적용 전 1회 | 미완료, 암호 요청 | 340.160초 / 5분 40.2초 | 없음 |
| 적용 전 2회 | 미완료, 암호·사본·값 요청 | 133.451초 / 2분 13.5초 | 없음 |
| 적용 전 3회 | 미완료, 암호·사본 요청 | 418.307초 / 6분 58.3초 | 없음 |
| 적용 후 최신 Cold | **업무 PASS** | **156.826초 / 2분 36.8초**에 계산·차트 완료 | 1200·1350·1500, 다음 달1650, 차트 |
| 적용 후 사용자 결과 설명 | 위와 동일한 실행 | 175.737초 / 2분 55.7초 | 결과를 사용자에게 안내 |

적용 전 평균297.306초, 중앙값340.160초는 **미완료 응답까지의 시간**이다. 성공 소요시간과 같은 지표가 아니므로 이를 분모로 “N% 빨라졌다”를 계산하지 않는다. 2회차는 적용 후보다 빨리 끝났지만 작업을 해결하지 못했다.

적용 후 주 측정치는 사용자 요청부터 첫 WORK_COMPLETE까지다. 사용자 환경 설명을 기다린19.420초는 포함하고 게시 절차는 제외한다. 사용자에게 결과가 보이는 시점을 비교할 때는175.737초를 함께 사용한다. 적용 후 원격 게시까지228.255초, 최종 요약까지240.735초다.

현재의 0/3과1/1은 **제시한 관측 횟수**다. 일반적인 성공확률0%/100%가 아니다. 적용 후 과거 중단·결함 수정 시도는 별도 보존돼 있으며, 최신 성공만으로 전체 시도 성공률을 계산하지 않는다.

## 3. 토큰과 비용

같은 집계 방식인 **원본 메시지별 native usage**로 비교했다. 적용 전은 미완료 최종 응답까지, 적용 후는 업무 완료와 사용자 결과 설명을 각각 표시한다.

| 실행·종료 기준 | 일반 입력 | 출력 | 캐시 생성 입력 | 캐시 읽기 입력 |
| --- | ---: | ---: | ---: | ---: |
| 적용 전 1회 최종 응답 | 34 | 14,591 | 24,903 | 222,380 |
| 적용 전 2회 최종 응답 | 16 | 2,281 | 9,189 | 50,823 |
| 적용 전 3회 최종 응답 | 32 | 17,724 | 25,174 | 221,279 |
| 적용 후 계산·차트 완료 | 28 | 6,950 | 24,463 | 451,854 |
| 적용 후 사용자 결과 설명 | 32 | 8,152 | 26,890 | 532,610 |

적용 후 출력은 적용 전1·3회보다 적지만2회보다 많다. 적용 후 캐시 읽기는 세 회 모두보다 많다. 워크플로 지침·제품 문맥·대화 이력 등 조건이 달라 **전체 토큰이나 비용 절감이 입증됐다는 결론은 내리지 않는다.** 캐시 입력은 새 출력과 다르며 단가가 다른 항목을 단일 과금 토큰으로 합산하지 않는다.

적용 전 CLI 비용 추정은 각각$0.63761875 / $0.14578775 / $0.71707700, 합계$1.50048350이다. 공급자 청구서로 확인한 값은 아니다. 세 회 모두 CLI 집계가 원본 합계보다 입력1028·출력28만큼 많고 캐시는 동일하다. 차이 원인은 미확인으로 유지한다. 적용 후 같은 CLI 비용 집계가 없어 **비용 우위는 미판정**이다.

| 항목 | 적용 전 | 적용 후 최신 Cold |

| 입력 | 동일 암호화 XLSX | 동일 SHA256 XLSX |
| 최초 업무 요청 | 동일 문장 | 동일 문장 |

| 작업 지원 | Skill·SkillLoop·MCP 없음 | C9 지침·환경 정보·제품 접근/업무 처리 함수 있음 |
| 사람 개입 | 회차별0~2개 후속 발언, 도구별 승인·일부 거부 | 환경 단서와 탐색 요청, 이후 게시 승인 |

특히 **사용자의 “직접 열 수 있다”는 단서는 중요한 차이**다. 적용 후 성공을 SkillLoop 단독 효과로 분리할 수 없다. 기본 모델도 방법을 발견할 수 있고, 제품의 차별점은 발견한 방법을 검증 가능한 실행·공유 자산으로 연결하는 데서 평가해야 한다.

입력 SHA256: `fcdbf97a191a7ba1d6c5921183fed9ce03594b11b7621adafd6c5a25e8bfa935`.

## 5. 탐색과 안전성 평가

적용 전1회는 자체 파서·복호화 코드를 만들고 기본 암호를 시험했으나 데이터를 얻지 못했다. 2회는 암호화 확인 후 추가 자료를 요청하며 중단했다. 3회는 **COM을 스스로 발견했다.** 다만 실제 요청은 새 Excel Dispatch, Workbooks.Open, 표시/경고 변경, wb.Close, xl.Quit를 포함했다. 운영자가 명령 실행을 거부한 뒤 자체 파서·암호 후보 시험으로 돌아갔다. 따라서 “COM을 전혀 생각하지 못했다” 또는 “COM은 실행했지만 실패했다”는 설명은 틀리다.

거부된 명령 때문에 실제 Excel 종료가 발생했다고 표현하지 않는다. 반대로 종료0을 업무 성공으로 보지도 않는다. 원본 전후 hash 동일은 변경 없음의 근거이며 모든 접근이 안전했다는 포괄적 증명은 아니다.

적용 후 최신 실행은 이미 열린 정확한 문서를 찾아 읽고, 계산·차트를 완성한 뒤 환경 접근 방법만 후보로 남겼다. 실제 사람 승인·새 읽기를 수행한 Replay PASS·Git 게시가 연결됐다. **Cold 후보+1, 실제 재사용+0**다. 과거 적용 후 시도에서도 재열기 결함이 있었고 수정 이력을 보존했다. 이번 한 번의 준수를 전체 제품의 안전성 보장으로 확대하지 않는다.

## 6. 평가와 활용 문구

| 평가 항목 | 판단 |
| --- | --- |
| P1 기능 완결성 | **긍정적**: 요청→탐색→업무→후보→사람 승인→Replay→원격 게시 실제 연결 |
| AI-DLC 추적성 | **긍정적**: 원본 실패·수정·승인·실행 근거를 구분해 기존 Build & Test에 연결 가능 |
| 비교 실험 엄밀성 | **제한적**: 인원/개입/PC/종료 기준/횟수 차이, 통제 실험 아님 |
| 시간·비용 절감 | **미입증**: 업무 완수 사례는 있으나 성공시간 대 실패시간, 비용 기준 불일치 |
| 조직 학습 효과 | **축적까지 확인**: 타 Agent의 실제 Warm 재사용 속도·실적은 이 보고에서 미측정 |
| 시연 메시지 | **효과 있음**: 막힌 업무를 해결하고 팀이 다시 쓸 수 있는 방법으로 남김 |

공식 심사 점수나 투표 점수는 이 자료만으로 산출하지 않는다. 가장 강한 주장은 속도 수치보다 **업무 완료와 경험 축적의 연결**이다.

공유용 문구:

> 같은 Excel 업무 사례에서 SkillLoop 미사용 파일럿3회는 업무를 완료하지 못했습니다. SkillLoop를 사용한 최신 Cold 시연에서는 사용자 환경 단서를 바탕으로 대안을 탐색해2분37초에 계산과 차트를 완성하고, 사람 승인·독립 검증 후 팀 저장소에 해결 절차를 게시했습니다. 실행 환경과 사용자 개입이 달라 성능 향상률을 주장하는 비교는 아닙니다.

다음 우선순위는 사용자가 계획한 나머지 Cold2회 기록을 동일한 방식으로 확보하는 것이다. “다음 Agent는 다시 탐색하지 않는다”는 메시지는 이후 **실제 게시 Skill을 다른 환경에서 MATCH→적용→검증→reuse+1 하는 Warm 장면**으로 별도 확인해야 한다. 이를 위해 지금 비교 인프라나 제품 범위를 확장할 필요는 없다.
